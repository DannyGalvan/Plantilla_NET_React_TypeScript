# ADR 0004 — Guid v7 como PK por defecto

- **Estado:** aceptado.
- **Fecha:** 2026-10-11.
- **Contexto:** el legacy usaba `long` autoincrement que requiere coordinación
  entre instancias y crea hotspots en escrituras concurrentes. Los Guid v4
  aleatorios generan fragmentación de índices.
- **Decisión:** `Guid.CreateVersion7()` (timestamp + random) como PK por
  defecto en las entidades nuevas (`Entity<TId>` sigue siendo genérico,
  un módulo puede usar `long`).
- **Consecuencias:**
  - Id portable entre motores (no depende de `rowversion` ni
    `auto_increment`).
  - Buen locality para outbox y event sourcing (orden aproximado).
- **Alternativas descartadas:** `Guid.NewGuid()` (v4, mala locality),
  ULID (otra librería), `long` autoincrement (hotspot en réplicas).
